    I/Os

    I/OIs dienen im weitesten Sinne ebenfalls der Kommunikation, weshalb wir hier einen Blick auf die Möglichkeiten werfen wollen.

    In |c| haben Sie die Library WiringPi verwendet, um auf die I/Os zuzugreifen. Diese Möglichkeit existiert in |python| ebenfalls - neben weiteren Möglichkeiten, die da sind (in alphabetischer Reihenfolge):

    • gpiozero <https://gpiozero.readthedocs.io/en/stable/>_

      Hier scheint mir folgende Anmerkung der Autoren dieser Lib interessant zu sein, denn sie deutet auf die relative Jugend dieser Library und auf den Umstand, dass sie auf (weiteren) I/O-Libs aufsetzt und sie so (komfortabel) erweitert:

      "GPIO Zero builds on a number of underlying pin libraries, including RPi.GPIO and pigpio, each with their own benefits. You can select a particular pin library to be used, either for the whole script or per-device, according to your needs. See the section on changing the pin factory."

    • pigpio

    • RPi
    • wiringPi

    Programminterne Kommunikation

    Diese Art der Kommunikation ist eine sehr praktische, wenn man

    • Programmteile entkoppeln möchte oder
    • Programmteile nur dann ausgeführt werden sollen, wenn bestimmte Ereignisse wie Parameteränderungen stattgefiunden haben.

    Wir beginnen mit einem einfachen Design und schreiben 2 Klassen, von denen die einen Parameter verwaltet und bei Änderungen des Parameters alle registrierten Klassen darüber informiert. Erster Klasse kann als Publisher bezeichnet werden, letztere als Subscriber oder als Observer.

    Dieses Design ist grundlegen und ist in Katalogen von Design Patterns unter Publisher-Subscriber Pattern oder Publisher-Observer Pattern zu finden.

    Installation

    Wenn Sie auf Linux sind, können Sie über Ihren Package-Manager installiern oder - noch besser und für alle Plattformen - Sie installieren per ::

    pip install paho-mqtt

    Es wird nur das Package installiert, das es Ihnen ermöglicht MQTT in Ihren Programmen zu verwenden. Ein Broker - siehe Message-Broker_ - wird nicht installiert.

    Message-Broker

    Kommunikation, die Publishers mit Subscribern verbindet, laufen meistens über eine zentrale [#] Instanz, einen sogenannten Broker. Eclipse Mosquitto - An open source :term:MQTTbroker <http://mosquitto.org/> ist ein Broker, der gerne genommen wird. Unter Linux installieren Sie am besten über Ihren Package-Manager. Unter Windows finden Sie unter Download <http://mosquitto.org/download/> einen Installer. [#]

    Wenn Ihre Programme miteinander kommunizieren sollen, muss ein Broker - in unserem Falle also Mosquitto <http://mosquitto.org/>_ - laufen.

    .. [#] Überlegen Sie sich, was das bedeuten kann!

    .. [#] Was Sie auch wann und warum installieren, Sie tun das immer auf eigene Gefahr!

    Publisher

    Um's kurz zu machen: Das ist das programm oder der Programmteil, der Daten über "Messages" publizieren möchte. Jede Message ist mit einer Id zu identifizieren - siehe z.B. MQTT Topics, Wildcards, & Best Practices - MQTT Essentials: Part 5 <https://www.hivemq.com/blog/mqtt-essentials-part-5-mqtt-topics-best-practices/>_.

    Subscriber

    Subscriber (oder auch Observer) sind Programme oder Programmteile, die sich für bestimmte Messages oder für eine bestimmte Menge von Messages registrieren können. Eine enstsprechende Methode wird ausgeführt, wenn die Messages, für die sich der Subscriber registriert hat, eintreffen.

    Fürs Debugging ist es ganz interessant, eine App zu haben, die das leistet und noch mehr. [#]_

    .. [#] So meldet sich z.B. MQTT Explorer <http://mqtt-explorer.com/>_ für alle Messages an.
