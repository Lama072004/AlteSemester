    Klassen

    Eine Klasse ist ein Bauplan für Objekte. Anstatt des üblichen Beispiels mit Cookie Cutter und Cookies, wählen wir ein technisches Beispiel - Sensoren.

    Beispiel Sensor

    Wir programmieren eine Klasse Sensor, die uns den Messwert eines realen Sensors liefern soll, der z.B. über einen I2C-Bus erreichbar ist.

    "Was muss ein Sensor können?", fragen wir uns jetzt. Wir fragen uns nicht, "Was muss ein Sensor haben?"!

    • Man muss einen Sensor vermutlich triggern, dass er eine Messung durchführt - Methode write_to_hardware (Vorschlag)
    • Man muss einen Sensor natürlich kesen können - Methode read_from_hardware (Vorschlag).
    • Man muss vllt noch Umrechnungen vornehmen. Das kann man natürlich in read_from_hardware machen, muss man aber nicht 2. Wir könnten also noch eine dritte Methode vorsehen: process.

    Die Reihenfolge, wie der Sensor angesprochen werden muss, wäre dann also:

    .. code-block:: python

    sensor.write_to_hardware()
sensor.read_from_hardware()
sensor.process()

    Aber halt! Wie kommen wir an den Messwert? value wäre eine Möglichkeit.

    Ctor / Dtor

    Ctor und Dtor stehen für Constructor und Destructor. Letzteren btraucht's in Python nicht, wir haben einen GC, von dem wir nicht wissen, wann er ausgeführt wird und unseren Dtor ausführt.

    Den Ctor braucht's aber meistens, denn hier werden die internen Daten angelegt. In unserem Falle sind das ein Attribut für den Messwert und vllt auch ein Attribut für den Status des Sensors. 3
